Key Concept — まず知っておきたいこと
資料をたくさん読ませると、AIの「作業机」が埋まる
📚 チャットに資料を全部貼ると…
AIが一度に見ていられる範囲（＝作業机の広さ／コンテキスト）には限りがあります。資料が多いほど机が埋まる。
①机が埋まると、AIは古い内容から「忘れる」。最初の資料の話が抜け落ちる。
②毎回すべて読み直すので動作が重く・割高になりがち。
③プロジェクトに保存すればスレッドをまたいでも資料は残る（前回学んだ通り）。でも“使う瞬間”に机へ広げる点は同じ。
④だから本命は 「全部広げず、必要な箇所だけ検索して渡す」 仕組み（＝RAG）。これがNotebookLMの正体。
ポイントは「全部読ませる」より「必要な所だけ探させる」。次のスライドで、その役割をどう分けるか見ます。

NotebookLM — あなたの資料専用のAI司書
「自分の資料の中だけ」で答えるから、ウソが減る
WHAT IS IT
あなたがアップした資料だけを読み込み、その中身についてだけ答えてくれるGoogleの無料ツール。例えるなら「自分の本棚しか見ない司書さん」です。
🔖 普通のAIは「世界中の知識から、それっぽく」答える。NotebookLMは「あなたの資料から、出典つきで」答える。だからハルシネーション（もっともらしいウソ）が激減します。
😵 ふつうのチャットAIに資料を全部貼る
机が埋まる・忘れる・出典が曖昧。「それっぽいけど資料に無い話」が混じることも。
📗 NotebookLMに資料を預ける
何冊でもOK。質問すると関係する箇所を探し、「資料のここに書いてあります」と出典つきで答える。
今日の使い方：複数のバラバラ資料をNotebookLMに預け、「要点は？」「目次（骨子）を作って」と頼む。整理された骨子を、次にClaudeへ渡します。

Claude CodeでNotebookLMにつなぐ方法（MCP接続）
0
前提を用意
Node.js（18以上）／ Google Chrome ／ Claude Code がインストール済みであること。
1
MCPサーバーを登録（コマンド1行）
ターミナルで Claude Code に NotebookLM 用のMCPサーバーを追加します。
claude mcp add notebooklm -- npx notebooklm-mcp@latest
2
Googleに一度だけログイン
Claude Codeで setup_auth を実行 → 開いたChromeでGoogleにログイン。認証はPCに保存され、毎回は不要（数週間で再ログイン）。
3
ノートブックを指定して質問
「NotebookLMの○○ノートブックに接続して、骨子と数字を取り出して」と頼むだけ。出典つきで返ってきます。
できること（主なツール）
  • list_notebooks … ノートブック一覧を取得
  • select_notebook … 使うノートを指定
  • ask_question … 出典つきで質問・回答
  • add_source … 資料を追加
⚠️ これは Googleの公式機能ではなく、有志が公開しているMCPサーバー（例：notebooklm-mcp）です。仕様変更で動かなくなる場合があり、機密資料の扱いは自己責任で。まずは試験的にお使いください。
もっと知りたい方へ：「NotebookLM MCP Claude Code」で検索 → GitHubの導入手順（README）に沿って設定。詰まったら無料相談でも一緒にセットアップできます。

Q&A / Contact
質問・ご相談はお気軽に
Q. NotebookLMは無料で使えますか？
はい、Googleアカウントがあれば無料で使えます。今日のデモ①（資料を預けて骨子を出す）は、全員がそのまま再現できます。
Q. 機密資料をAIに入れて大丈夫？（NotebookLMやClaudeなど）
これはAI全般に共通する注意で、無料版は入力が学習に使われる場合があるため、社外秘は基本NG。今日のNotebookLMも例外ではありません。ただしNotebookLMは「入れた資料の中だけ」で答え出典も追える設計で、比較的扱いやすい部類。重要資料は必ず社内ルールの確認を。
Q. デモ②（Claude Code）は初心者でも？
上級者向けです。まずはデモ①の「NotebookLM→Claude」だけで十分。慣れてから②に進むのがおすすめです。手順は資料に残します。
